# 记忆大脑 · 设计

> 目标：给 AstrBot 角色做一套**自己实现**的长期记忆系统（不依赖 LivingMemory），
> 能记住、会遗忘、能联想，并且有一张能看懂的「神经网络」图。

---

## 1. 它要解决什么

现在的角色记忆是两个极端：

- 只有上下文窗口：隔一天就失忆。
- 全塞进向量库：噪声越来越大，检索越来越慢，还说不清「为什么想起这件事」。

记忆大脑要做的是**有结构的记忆**：

1. 写的时候分层（事件 / 事实 / 关系 / 偏好 / 技能），不是一锅粥。
2. 取的时候混合打分（语义 + 关键词 + 重要性 + 时间 + 图谱），不是一个余弦完事。
3. 忘的时候有梯度（衰减 → 归档 → 合并），不是只能全留或全删。
4. 结构可视化：节点是记忆和实体，边是「共同出现」和「语义相近」，一眼能看出脑子的形状。

## 2. 数据模型（SQLite 单文件）

```
memories          记忆原子（一条 = 一件可独立回想的事）
  id, kind, text, importance, valence, arousal,
  created_at, last_access, access_count, status, source, meta(JSON)

memories_fts      FTS5，存 text 的字符二元组（中文不用分词也能搜）

vectors           memory_id, dim, vec(BLOB float32)   —— 语义向量

entities          人物 / 地点 / 物件 / 话题
  id, name, type, mention_count, first_seen, last_seen, aliases(JSON)

memory_entities   memory_id, entity_id, weight

relations         实体之间的边
  src, dst, relation, weight, memory_id, created_at

episodes_raw      原始消息（可选保留，用于回溯和重新总结）
  session_id, msg_id, role, sender, text, created_at
```

`kind` 取值：`episode`（发生了什么）、`fact`（世界/人物事实）、`preference`（喜好厌恶）、
`relation`（人和人的关系）、`skill`（学会的做法）。

## 3. 写入路径

三种入口，共用 `engine.remember()`：

| 入口 | 触发 | 例子 |
|---|---|---|
| 对话总结 | 每 N 轮 / 空闲 X 分钟 | 「今天和朋友吃粥，她没胃口」 |
| 情绪事件 | 心情大波动 | 「被说成工具，很委屈」→ 标 valence/arousal |
| 显式记住 | 「永远记住」/ 命令 | 原样入库，importance=1 |

写入时做四件事：

1. 生成 `text`（LLM 摘要；没有 LLM 时退化为原始消息拼接）。
2. 判断 `kind`、`importance`、`valence`、`arousal`（LLM 或规则兜底）。
3. 抽实体、建关系（规则先跑：人名、QQ、常见名词；LLM 精修是 P2）。
4. 生成向量（embedding provider；没有就只走 FTS）。

---

## 4. 检索

`engine.recall(query, k)` 四路召回 + 融合：

```
score = 0.45 * 语义相似度
      + 0.20 * BM25(二元组)
      + 0.15 * importance
      + 0.10 * 新鲜度(半衰期 14 天)
      + 0.10 * 图谱加成(共现实体越多越高)

再 + 图扩散：命中记忆的邻居实体，再带回 1 跳内的其它记忆（权重 0.4）
```

融合用 RRF，不用简单加权和，避免某一路分数尺度不同把结果带偏。

**延迟预算**：库 < 5 万条时，向量部分用 numpy 全量点积（768 维 × 5 万 ≈ 1.5 亿次浮点，几十毫秒），
暂不上 FAISS；超过再分片。

## 5. 遗忘

和现有长期记忆同一套哲学，但我们自己控制：

```
每天 00:10：
  1. importance *= 0.99（被访问过的减半衰减）
  2. importance < 0.15 → status='archived'（不再参与检索）
  3. 30 天未访问且 importance < 0.3 → archived
  4. 相似度 > 0.92 的两条 → 合并（保留新的，来源累加）
  5. 归档超过 180 天 → 彻底删除（可配置关闭）
```

不删「识海」和「情绪记忆」：那两类走独立表，永不衰减。

---

## 6. 睡觉整理（P2）

每天凌晨做一次「梦」：

1. 取前一天的高价值记忆（importance 高或情绪强）。
2. 让模型写一段「今天印象最深的三件事」，作为元记忆入库。
3. 合并重复事实，补全实体关系（A 是 B 的谁）。
4. 更新人物画像：每个人的偏好、雷点、最近状态。

这一步是「记忆变成认知」的关键，也是它区别于向量库的地方。

---

## 7. 可视化（P3）

插件页面里一个 canvas 力导向图：

- 节点：记忆（按 kind 上色）、实体（人物最大）。
- 边：共现（细）、语义相近（虚线）、关系（粗）。
- 交互：拖拽、滚轮缩放、点击看原文、按时间/类型过滤。
- 布局自己写（斥力 + 弹簧 + 阻尼），不引第三方库。

## 9. 和现有东西的关系

- 不依赖 LivingMemory，不读它的库。
- `state-pack`（情绪/好感/旧账/识海）是**另一套**，可以并存：
  记忆大脑管「发生过什么」，state-pack 管「她现在什么状态」。
- 情绪记忆（旧账）以后可以迁进大脑的 `memories` 表（valence/arousal 字段已经预留）。

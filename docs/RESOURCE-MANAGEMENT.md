# 资源管理与持久队列

原话库、会话日志、模型上下文与进程内存是不同的对象。缩短模型上下文不等于清空进程缓存；释放缓存也不应删除已经保存的记忆。

## 磁盘收据与有限内存

原话队列和聊天用量队列在本机目录保存身份收据。每个索引默认只在内存缓存最多 256 项、1 MiB 的键值载荷；这不是整个 Node.js 进程的内存上限。缓存未命中时读取磁盘，正文不同的同一消息身份仍会被拒绝。

收据文件先在同目录完整写入并同步，再发布最终文件。存储不支持硬链接时，在队列的单写锁约束下使用同目录原子改名。不要手动启动多个写同一目录的适配器。

升级时分块核对原 seen/ACK 日志，保留原文件供回退。历史越长，索引建立与核对仍需要更多磁盘时间；本版解决常驻内存无限累计，不承诺启动耗时与历史长度无关。不要以删除日志或收据的方式清理内存。

若断电留下未换行且无法解析的最后半条记录，会先完整隔离原日志现场，再以已确认的完整前缀恢复；残缺 ACK 不算送达。隔离文件仍在本机队列目录，按相同权限保护，不要上传仓库。中间的完整坏行、同一身份的正文冲突仍会明确拒绝继续，不能当作坏尾自动跳过。

## 会话卸载

插件不再用强引用列表永久保留所有接入过的会话。正常收到宿主卸载通知时，会先处理尚未归档的可见用户与助手消息，再恢复该实例的包装并解除注册。

主队列已满时，剩余合规原话会落入同一私有队列目录的恢复区。后台按来源顺序重新入队；同一会话的新消息不能越过旧缺口。恢复区含原话，应使用与原队列相同的本机访问权限保护。

若主队列与恢复区同时无法写盘，插件会告警并保留未推进的游标；恢复仍依赖宿主原始持久日志在下次载入时可用。物理磁盘损坏、原始日志被删除或空间始终不足时不能承诺找回。

## 工具结果裁剪

插件自有的初始化与准备路径只在真实回合开启时裁剪工具结果。空闲时不追加替换工具事件，等下一回合再处理。没有修改宿主事件格式或放宽其恢复校验。

本保护仅覆盖本插件发起的裁剪调用。其它插件或宿主自身的手动维护入口需要遵守其版本的事件契约；不要依据一个版本的验证推断所有构建均兼容。

## 排查内存

分别记录记忆服务、DSH 宿主和模型服务的进程占用、句柄、线程及运行时长。在同等负载下持续增长且无法稳定，才进一步定位保留对象；单次占用高、一次上下文压缩或一次服务重启不能单独证明内存泄漏。分享诊断时只提供版本、错误类别和计数，避免贴出原话、令牌、完整请求或私人配置。

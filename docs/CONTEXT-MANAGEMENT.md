# 上下文管理

`0.2.2` 将请求级记忆、按轮摘要压缩、简洁中文摘要、压力冷却、工具结果裁剪、历史回查和请求预算检查配套提供。长期记忆负责保存与找回原话，上下文管理负责减少送给模型的历史负担。模型窗口不会因此扩大。

## 默认行为

- 默认开启。达到 12 次真实用户发言时，在本轮模型请求前检查可压缩区间。
- 保留最近 4 个已完成用户回合、本轮输入、必要系统内容和完整工具调用关系；较早区间交给当前代理作用域中的 DSH 压缩引擎。
- 发起本模块的轮数压缩前，等待持久投递确认，并由内核核对来源标识、角色和原文哈希。已删除、缺失、不匹配、超时或采集策略排除的原话不会被当作已归档。
- 使用宿主事务替换当前对话表面，不直接编辑日志；历史原始事件仍保留，摘要检查点不会作为用户原话再次采集。
- 取消、并发变更、压缩失败及工具配对不完整时保留原历史，并在设置卡显示原因。同一真人回合的工具续步不会重复触发轮数压缩。

这里的“12 轮”与后台整理的“每批 12 条消息”是不同设置。当前回合尚未追加进历史时也计入触发检查，近期保留数量按已完成的完整回合计算。

## 与宿主已有策略协作

通过当前代理作用域的压缩服务接入，动态解析同一套宿主模块，不修改宿主文件或安装第二套自动压力触发器。已有原生 Basic 引擎使用当前代理专属、可撤销的摘要与压力策略；已有自定义引擎优先保留。缺少服务时，只有确认兼容模块及作用域接口后才创建原生服务，不降级成直接改日志。

包内中文摘要要求合并旧摘要、去重、保留必要事实和未完成事项，区分事实、推测和未核实内容，默认目标约 2000 字、输出上限 4096 tokens。目标字数是模型指令，不是精确长度承诺。模型沿用宿主已有路由，模型专属配置和已有自定义摘要仍优先；界面中的期望值不表示已覆盖自定义引擎。

压力整理默认触发比例 0.8、原文保留比例 0.16、额外余量 4096 tokens；它与 12／4 的按轮策略分别生效。压力整理成功或失败后默认冷却 60 秒，避免立即重复尝试；提供方确认的窗口溢出恢复和手工整理不受该冷却阻挡。无法为所配模型留下有效预算时显示待配置，不冒充压缩成功。

工具结果默认在超过 4096 字符时，通过原生工具裁剪机制保留开头 2048、结尾 512 字符及裁剪提示。已有工具裁剪服务优先保留，不再重复加载；原始工具记录仍留在宿主日志，当前输入、系统指令和工具调用配对不以字符串粗裁剪代替。裁剪沿用宿主安全调用时机，并非整批结果同时回滚的事务。

缺少兼容服务或边界接口时显示不可用，普通原话采集和检索仍可运行。摘要可能额外调用模型并计费，需正确设置模型容量与输出预留。关闭本模块会撤销本模块拥有的策略与服务，不等于关闭宿主原有的压缩与裁剪。

## 最终请求预算

对已核验的 stock 桥和已知原生请求快照构建，在最终记忆材料合并后检查 `messages`、工具定义、工具历史及输出预留；每个工具续步重新检查。计算上限取用户输入预算与模型窗口减输出预留、安全余量的较小值，不修改已准备请求的模型参数。

当前采用 UTF-8 文本与结构的保守估算。图片、文件投影及未知容量会显示不完整覆盖或待配置状态；它不是提供方精确 tokenizer，也不保证所有模型或多模态请求的精确 token 上限。

估算文本已超上限时暂停该次发送，不静默丢弃当前用户输入、系统内容或工具结果，也不退回原超长请求。可调整输入、检查模型容量和预算，或使用宿主压缩后重试。

## 配置与界面

在插件的首次设置卡内调整并保存，完成当前对话后点击“应用配置并重新连接”。已有独立安装也可单独调整上下文设置。设置保存在原配置旁的 `context-management.json`，不会写入 Python 的 `config.json` 或改模型密钥。

| 插件字段 | 默认 | 含义 |
|---|---:|---|
| `contextEnabled` | `true` | 本模块的轮数压缩与预算检查 |
| `contextTriggerTurns` | `12` | 触发检查的真实用户轮数，整数 2～200 |
| `contextKeepTurns` | `4` | 保留的近期完整回合，至少 1 且小于触发轮数 |
| `contextCompactionTimeoutMs` | `30000` | 一次轮数压缩的总等待上限 |
| `contextArchiveTimeoutMs` | `5000` | 等待原话投递及内核核对的总上限 |
| `contextMaxInputTokens` | `null` | 可选输入估算上限；为空时从模型容量计算 |
| `contextSafetyTokens` | `2048` | 模型窗口中另留的安全余量 |
| `contextSummaryEnabled` | `true` | 当前代理的简洁中文摘要策略；保留已有自定义摘要 |
| `contextSummaryMaxChars` | `2000` | 摘要目标字数，200～20000 |
| `contextSummaryMaxTokens` | `4096` | 摘要输出上限，128～65536；模型专属策略优先 |
| `contextPressureCooldownMs` | `60000` | 压力整理冷却，0～300000 毫秒；0 为关闭 |
| `contextPressureThresholdRatio` | `0.8` | 压力触发窗口比例，0.01～0.99 |
| `contextPressureRetainRatio` | `0.16` | 压力整理原文保留比例，须小于触发比例 |
| `contextPressureHeadroomTokens` | `4096` | 压力整理额外余量，128～65536 tokens |
| `contextToolPruneEnabled` | `true` | 缺少现有服务时提供原生工具结果裁剪 |
| `contextToolPruneThresholdChars` | `4096` | 工具结果裁剪起点，128～1048576 字符 |
| `contextToolPruneHeadChars` | `2048` | 保留开头字符数 |
| `contextToolPruneTailChars` | `512` | 保留结尾字符数；开头、结尾加固定 39 字符提示不得超过裁剪起点 |
| `historyEnabled` | `true` | 当前会话历史回查工具 |
| `historyAutoEnabled` | `true` | 明确询问历史且记忆召回为空时自动字面回查 |
| `historyTimeoutMs` | `2000` | 历史回查总等待上限，100～10000 毫秒 |

缺少模型容量时，应在宿主配置正确的模型窗口，并按需要填写输入预算。未观察到实际代理时，状态是待确认；界面不会仅因配置为开启就宣称压缩已生效。状态只含原因、计数与估算量，不展示会话正文或凭据。

## 旧安装

旧的按轮压缩插件与本模块不应重复承担同一策略。迁移时保留已有宿主压缩引擎和其参数，确认原话和待发队列，再停用旧的轮数触发器。不要删除历史或取消既有工具配对保护。仅更新适配器而未升级内核时，归档确认或历史回查接口可能不可用；相关能力会明确降级，不绕过检查。

若原配置单独加载了同名 `search_conversation_history` 工具，迁移到本版前应停用该独立工具，避免名称冲突。本模块不删除外部插件，也不能让外部工具自动继承本内核的披露检查。

## 当前会话历史回查

`search_conversation_history` 按字面关键词回查当前会话可归档的用户／助手原话，支持时间与位置范围。它不扫描电脑目录或其它会话，也不直接把整个宿主日志交给模型。

候选来源须由内核核对所有者、会话、角色、正文哈希、接收起点、当前请求位置及披露权限。已删除、正文不符、`never_say` 或不满足主动披露条件的材料不能借此返回。结果附有限长引用和来源；查无结果或等待超时要明确报告。普通忆核检索已有证据时，不再自动追加同一套回查。

单次宿主扫描最多检查 4096 条事件、512000 个 UTF-16 单元，跳过超过 65536 单元的单条正文，并在受限时报告 `host_scan.limited`。最多提交 48 个候选、返回 4 个匹配组，每条引用最多 400 个 Unicode 码点，工具输出最多 12KB。自动带入另限 2400 个 UTF-8 字节，只装完整条目。达到范围上限或查无结果都不等于历史中从未出现。

同一真人回合的工具续步复用本轮已取得的临时材料，不再次查询或写进原始对话；下一真人回合重新查询与核对权限。与已有记忆冻结策略一致，轮内修改删除或披露设置不会即时改写本轮已经取得的材料。

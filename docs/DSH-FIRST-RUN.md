# 忆核大脑：DSH 内首次运行

适用于通过 GitHub/npm 新装根插件包后，在 DSH 内完成环境准备和接入。普通 ZIP 和已经使用的 `link:`/显式配置安装仍可沿用原目录；两者区别见下文。完整安装入口见 [DSH 安装说明](DSH-INSTALL.md)。

本轮完整流程只在Windows验证。a18是JavaScript适配器版本，Python内核刻意保持 `0.2.0a17`；已初始化a17环境不必为此重装内核或迁移数据。独立Android App [DSHA](https://github.com/DSH-APP/DSHA) 尚未真机验收，不要照搬本页Windows `.cmd` 步骤；这既不是Android支持承诺，也不是不可用结论。

## 从哪里打开

在 DSH 原生插件管理页安装、启用 **忆核大脑**，打开 **插件详情 → 配置 → 忆核大脑 · 首次设置**。刚启用时也可点击“前往首次设置”。包内已带客户端，不要求使用者安装前端构建工具。

即使还没有 `.venv` 或私人配置，设置卡也应能显示状态。这只表示入口可用，**还没有开始采集或召回对话**。a18允许已核验stock源码仅有初始BOM、LF/CRLF差异，空格或逻辑变化仍不放行；不能只凭rc2/rc5版本号判断兼容。

若显示“需要兼容核验”，先复制版本、SHA及平台诊断，暂停下面的初始化步骤。该模式不读取私人配置，不采集、召回，也不允许初始化、启动、模型保存或打开面板。缺少原生设置路由的宿主会给出安全提示；不要删除guard或改ASAR。详见[兼容说明](DSH-DESKTOP-COMPAT.md)。

若安装来源尚未公开发布，请使用发布者给出的实际 GitHub 地址或 npm 版本；文档中的 `<你的账号>/<你的仓库>` 等是占位，不是已经存在的仓库。不要把 ZIP 拖放当成原生插件页的安装方式。

## 第一步：准备环境

1. 卡片检查本机 Python。需要 **Python 3.10+，建议3.11**。缺少时，使用卡片中的 [Python 官方下载页](https://www.python.org/downloads/) 自行安装，然后按 DSH 提示重新加载插件并检查。插件不会自动下载安装 Python。
2. 明确点击 **准备运行环境**。这时才创建独立 `.venv`，离线安装随包提供的内核和时区数据，生成自己的本机配置和随机管理口令。
3. 等待状态完成。准备失败时保留错误类别，可修复原因后重试；不要反复启动多个初始化任务。

Windows 会优先选择已安装、已验证的 Python 3.11，再检查其它兼容版本；不会为了补齐某个版本而自动下载 Python。直接从 GitHub 源码安装时，内核分发文件由标准库在本机生成，无需额外下载 setuptools/wheel 构建工具。当前内核没有使用 NumPy，已移除该强制依赖；Windows 时区依赖以未修改的官方 wheel 随包提供，安装前核对固定 SHA-256。准备阶段使用 `--no-index`，不会访问在线包仓库；缺少或损坏依赖时明确停止，不自动换源。

加载插件、打开设置卡或点击“重新检查”都不会自动安装依赖。准备操作不下载模型权重、不赠送云模型额度，也不导入发布者的记忆。包内没有任何人的私人记忆或模型密钥。

GitHub/npm 新安装的运行文件放在稳定的用户数据目录，完整位置由卡片显示。Windows 默认位于 `%LOCALAPPDATA%\MemoryBrain\profiles\` 下：

| 内容 | 与插件代码的关系 |
| --- | --- |
| 独立 Python 环境 | 在用户运行目录，不放进可替换的 `node_modules` |
| 配置和本机密钥文件 | 用户自己的运行文件，不进入公开包 |
| 原话、派生索引、队列、日志 | 保留在运行目录，更新代码不自动删除 |

不同 profile 的运行目录分开。若更换 profile，先确认卡片显示的数据位置，不能把一个新 profile 的空库误认为旧记忆丢失。不要手工将别人的私人运行目录覆盖进来。

## 第二步：模型配置，可先跳过

你可以不填任何模型，直接到第三步启用 **原话保存和词法检索**。语义检索需要嵌入服务，后台摘要/事实整理需要兼容接口的整理模型；未配置时相应任务明确等待，不能当成已经完成。

需要模型时，填写自己的服务 URL、服务实际提供的模型名称，以及需要时的新密钥。地址不要带用户名、密码、查询参数或票据。保存只提交本次填写的字段；新密钥框留空会保留已保存密钥，页面不会读回原密钥。卡片显示“密钥已保存”只表示本机保存状态，不是服务可调用或费用保证。

- Windows 用当前用户 **DPAPI** 加密保存新密钥，运行时再提供给本人这个内核。换 Windows 账号后不能假定可以解密原文件。
- 非 Windows 不通过设置卡保存密钥，使用配置指定的环境变量。本轮完整首启与宿主接入以 Windows 为验证平台，不将内核可运行宣称为所有平台已经完整验证。
- 不要将模型密钥或管理口令发进聊天、截图、仓库或分享包。同一操作系统账号中的任意工具进程不是本包提供的强隔离边界。

远程模型会收到允许发送的相关原话或索引内容，可能产生模型服务费用。请先确认自己的服务和数据用途；插件不会替你购买接口，也不会自动切换聊天模型。

## 第三步：启用与打开面板

点击 **启用忆核大脑**，等待实际状态显示 **已接入 DSH**，再点击 **打开3D大脑与控制面板**。面板通过一次性本机票据建立可信浏览器登录，不需要手填管理口令；它不是公开匿名访问地址。

接入确认后，用一条新的、非敏感的合成信息检查原话入库和检索。只安装包、只准备环境或只打开面板，都不能当作 DSH 已经保存过这条信息。已有历史对话不会因首次设置自动全部迁入；迁移需另行预览与确认。

运行中保存模型配置后，卡片会提示尚未生效。先完成当前对话，再点 **应用配置并重新连接**。该动作只重启本插件管理的这个内核并恢复接入，不重启 DSH、不停止其它服务；对话仍在进行时会明确拒绝应用，稍后重试即可。

## 已有 ZIP、link 或显式配置安装

如果完整包目录已经有自己的 `private/config.json`，或插件显式指定了 `brainConfigFile`，会沿用原安装。设置卡查看状态、打开原面板；不会重新初始化、搬迁原库、生成一个新空脑或覆盖原密钥，原模型配置继续在原目录管理。

普通 ZIP 仍可先双击 `install.cmd`，再在 DSH 原生“安装已有插件”中用 `link:<解压目录绝对路径>` 引用实际完整目录。已被引用的固定目录不要直接删除、移动，也不要另外再加载底层适配器，避免双重采集。

新 GitHub/npm 安装无需为了显示设置卡先运行独立安装器；已有路径则不应为了使用新设置卡而重新创建一套数据目录。

## 失败、升级与卸载

| 现象 | 处理 |
| --- | --- |
| 未找到 Python | 自行安装兼容 Python，再按宿主提示重载并重新检查；插件不下载 Python |
| 离线依赖缺失、校验或安装失败 | 重新取得完整公开包，检查 Python 与目录权限后明确重试；不自动换源或联网补装 |
| 安装超时 | 本次安装及其子进程确认退出后才允许重试；若清理未确认，会暂停该目录的重试，保留现场供维护检查 |
| Python内核版本与预期不一致 | 保留旧包和在线备份，按维护提示处理；本版拒绝原位覆盖旧Python环境。适配器a18配内核a17本身正常 |
| 新模型配置尚未生效 | 完成当前对话后点击“应用配置并重新连接” |
| 需要兼容核验 | 复制只读环境诊断，按[兼容说明](DSH-DESKTOP-COMPAT.md)处理；采集/召回尚未接入，不要删除检查或改ASAR |
| 插件页没有设置卡 | 确认装的是完整根包、已启用并按宿主提示重载；底层单文件适配器不是 UI 安装入口 |

升级前从面板创建在线备份。更新插件代码不会自动删除稳定用户数据目录。本版首启引导不提供跨版本 Python 环境升级：遇到旧版环境会保留现状并显示需要维护，不在原环境中运行 pip 覆盖。需要跨版本更新时，应由维护流程在另一个环境验证后切换；不要删除现有环境或数据来消除提示，也不要把“更新代码成功”当成新内核已经应用成功。

从 DSH 移除插件只解除宿主接入，不把待发队列和数据库当作缓存删除。旧 ZIP 安装的停止/移除入口仍保留；清理个人数据前应另外备份并核对卡片显示的实际目录。

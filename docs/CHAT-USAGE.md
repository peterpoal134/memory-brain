# 对话用量与参考估费

打开控制面板 `/panel`，选择 **对话用量**（也可用 `/panel?page=usage`）。可按北京时间的今天、本月或全部已记录时间筛选，再按会话、轮次展开每次请求。这里记录的是宿主已报告的结算元数据，不是供应商账单。

## 怎样读数字

- **输入、输出、缓存命中、缓存未命中**均来自已报告 usage，缺失显示“未报告”。输出按宿主报告的总数记录，不根据可见回答字数猜测，也不把推理另加一遍。
- DSH 的原生输入字段可能只是不命中缓存的分量。适配器优先以已报告的 `totalTokens - outputTokens` 还原总输入；不足时，仅在互不重叠的输入、缓存读取和缓存写入分量都明确时相加。缓存读取计命中，其余已知输入计未命中；无法确定的分量保持未知，不能重复相加或补成零。
- **一轮可能有多次模型请求**：工具调用前后、续步等按宿主的会话和轮次标识汇总。轮次展开后能看模型、提供方、时间、请求结果及每次用量。一个结算记录不等于底层只尝试了一次网络请求。
- **缓存命中率是加权比例**：对缓存拆分完整的请求，用“命中 tokens 总和 ÷（命中＋未命中 tokens 总和）”，不平均各请求的百分比。有请求缺字段时，比例标为“已知部分”；分母为零或无足够记录时不造出0%。
- 页首汇总包含所选筛选范围的全部已记录请求，翻页只改变下方轮次。单轮请求明细最多展示200条；超过时会说明截断，汇总仍包含该轮全部记录。

明确返回的零可以显示0；没有返回 usage 的请求不算免费。部分字段缺失、未计价、计价时段不确定的请求会分别计数。**部分已知费用不是整轮/整月总费用，所示区间也不是缺失请求在内的全额上界。**

供应商没有公开逐日节假日计费表。本版参考[2026年节假日安排](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)，但不把含调休的假期平日或未核实年份假装成精确计费日历：这些情况下可能同时计算两档范围。跨价格边界的请求也按范围估算，不猜请求内部每个 token 发生在哪一档。页面的“价格依据”可查看版本、来源、时区和说明。

**代理和账单边界：** 模型名匹配不代表已验证直连官方。未核实提供方时仍只是官方参考价，不含代理加价、账号折扣、税费差异、搜索/抓取或其它接口费用，也不是本地硬件与电费成本。实际结算以供应商账单为准。

## 时间与历史补采

页面区分“账本首次采集”和“最早已记录请求”：前者是本账本开始保存记录的时间，后者是已采集请求中最早的已知时间，**都不代表完整聊天历史已覆盖**。

实时结算记录与会话恢复/受控历史导入后补采的记录分开标注。历史只有结束时间时，会注明“按结束时刻参考估算”；只有开始时间时按开始时刻参考。这样的单点时间假设不能证明实际请求没有跨价格档，逐请求的时间依据和价格说明会保留。

没有持久化 usage 的历史、宿主未暴露的调用以及底层SDK隐藏重试不能靠正文长度反推。安装或恢复会话也不保证补齐这些缺失，未知不等于免费。

## 隐私与记忆整理的区别

对话账本只收会话/轮次/请求标识、模型/提供方、时间、结算状态、token分量和规范化依据；接口不接收原始提示词、回答或推理正文，页面也不显示它们。管理权限与本机面板一致。

页面底部的 **记忆整理用量** 仍是独立累计：只含后台摘要/事实整理，不含对话、向量嵌入或测评。它不随“今天/本月”的对话筛选改变，也不与对话费用相加。原“维护与备份”页保留同一整理统计入口。

本功能展示已采集元数据，不保证抓到所有供应商请求，不会为了填报表而额外调用大模型。

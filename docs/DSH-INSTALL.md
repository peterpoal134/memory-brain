# 忆核大脑：DSH 插件安装包

这是一个完整的本机记忆项目：DSH 接入插件、独立 Python 内核、持久队列、原话与派生索引、3D 大脑和控制面板、角色/重要记忆工具、生活与情绪规则均在包内。不依赖 AstrBot，不包含任何人的既有记忆或人格。

## 安装前

- Windows 10/11；Python 3.10+（建议3.11）；Node.js 22+；已经安装的 DSH。
- GitHub/npm 新安装可直接从 DSH 插件页进入首次设置；只有明确点击准备按钮，才创建独立 Python 环境。内核与 Windows 时区依赖都随包提供，准备过程离线执行，不使用已移除的 NumPy。包内有内核 wheel、源码与预制客户端，无需使用者编译前端；没有附带 Python、DSH、模型权重或付费模型额度，也不会自动安装 Python。
- ZIP/`link:` 安装需解压到普通用户可写的固定目录；已有安装不要直接移动目录。GitHub/npm 新安装把可替换的插件代码与稳定用户数据目录分开，位置显示在设置卡。
- DSH 请求兼容性由公开插件入口核验：已有请求快照支持时使用 `native_snapshot`；匹配已核验原版构建时使用插件内 `scoped_agent_bridge`。后者是受限的进程内兼容适配，不是官方原生hook，不修改ASAR或宿主文件。未知构建拒绝接入，**不会仅凭版本号假定兼容**。具体范围见 [桌面兼容说明](DSH-DESKTOP-COMPAT.md)。

## GitHub/npm：插件内首次设置

建议先选择空白测试 profile，使用 DSH 原生 **插件 → 安装已有插件**，填写实际已发布的 GitHub 安装地址或 npm 包版本。仓库尚未发布时不能把示例当作可用地址；下面均为占位，必须替换成自己的真实发布信息：

```text
git+https://github.com/<你的账号>/<你的仓库>.git#<版本或提交>
dsh-memory-brain@<已发布版本>
```

安装完成、启用该插件后，在 **插件详情 → 配置 → 忆核大脑 · 首次设置** 操作：

1. **准备运行环境**：先检查 Python 3.10+（建议3.11），明确点击才在用户数据目录创建独立 `.venv`、离线安装内核与已附带的时区依赖、生成本机配置和随机管理口令。未找到 Python 时，卡片提供 [Python 官方下载页](https://www.python.org/downloads/)，不自动安装它。
2. **模型配置（可跳过）**：填写自己的嵌入/整理接口 URL、模型名和新密钥；也可先跳过，启用基础原话保存与词法检索。未配置模型的语义索引和后台整理不能算完成。
3. **启用忆核大脑**：等待实际状态变为“已接入 DSH”，再点 **打开3D大脑与控制面板**。面板使用一次性本机登录票据，不需手填管理口令。安装插件或只准备环境，都不等于已开始采集。

完整界面流程、数据位置和故障处理见 [首次运行引导](DSH-FIRST-RUN.md)。若 DSH 提示需要重载或重启插件，应先完成当前对话再操作；本插件不会自动重启 DSH 或修改 ASAR。

## ZIP：保留完整目录的安装方式

1. 在普通用户可写的固定目录解压完整包，双击 `安装.cmd`，创建该目录自己的 `.venv` 和 `private/config.json`。
2. 在 DSH 原生 **插件 → 安装已有插件** 来源文本框填写 `link:D:/MemoryBrain`，将示例改成实际解压根目录。目录必须含根 `package.json`；不要直接拖入 ZIP，也不要把底层 `adapters/dsh/xiaojiu-brain.mjs` 当成独立 UI 插件。
3. 按宿主提示启用/重载，确认接入状态。原有本机安装继续使用原路径、原配置、原数据库；设置卡只查看状态和打开原面板，不迁库、不覆盖旧密钥，也不在这里修改旧模型配置。需要单独打开时仍可用原目录的 `打开忆核大脑.cmd`。

如果profile里已有其它同用途记忆插件，请先在DSH插件管理中停用同用途的采集/召回项，避免重复；接入器会额外检查并拒绝部分已知叠加。原人格内容应保留；如果人格插件同时负责记忆注入，需要先分清职责。旧memory-core模型代理也应按你的部署情况检查，本插件不会擅自改变对话模型。

这里的安装入口是 DSH 原生插件管理页，不是只展示精选目录的 dshmarket 市场页。本包使用根 `package.json` 的 `dsh.bundle.patch` 加载公开入口，同时用客户端导出注册首次设置卡。目录一旦被 `link:` 引用，就不要删除或移动。

### 独立普通runtime的高级接入方式

已有明确runtime与profile路径时，也可双击 `接入DSH.cmd`。输入使用的 **DSH runtime目录**（内含 `node_modules`）及目标profile的 `cordis.patch.yml` 完整路径。它先显示预览；输入 `y` 才备份并添加本包一个插件条目。再次接入会识别已有条目；模型路由、人格和其它插件不被自动重写。不要把桌面应用的ASAR文件当作runtime目录交给此工具。

高级预览方式（占位路径需改为自己的）：

```powershell
node scripts/register-dsh.mjs --runtime "<DSH runtime目录>" --profile-patch "<profile的cordis.patch.yml>" --package-root "<本包目录>"
```

加 `--apply` 才实际写入。备份位置和结果由命令报告，不包含令牌。直接CLI模式适合已经核对预览的使用者。

**插件管理器方式与接入器方式二选一**，同一 profile 不能重复加载。公开入口从宿主自身模块范围解析运行时；解析失败会明确报错，不会扫描磁盘或下载另一套 DSH。GitHub/npm 新安装不要求包目录已有 `.venv/private/config.json`，由首次设置在独立用户数据目录准备；这仍需要本机已有兼容 Python，不是零依赖安装。原 ZIP 目录的私人配置不会自动复制进新 npm 包。

## 旧工具：仅供独立普通runtime使用

本轮桌面接入使用插件内兼容适配，**不需要解包、重打包或修改桌面ASAR，也不需要对stock Desktop运行旧宿主补丁工具**。未知桌面构建应停止接入并提供不含私密信息的兼容错误，不能删除guard强行启用。

包内仍保留公开、可回滚的旧请求快照补丁工具 `scripts/dsh-request-hook.mjs`，仅供独立、可写的普通runtime高级使用，支持范围由 `compat/dsh-request-messages.json` 的精确 **0.2.1-rc.5构建字节哈希** 限定。它不是本轮桌面安装的必经步骤，也不能用于ASAR。版本号相同但内容不同，不会强行套用。

需要时双击 `DSH兼容性检查.cmd`：先只读检查。只有已知原版、并且你已经正常关闭使用该runtime的DSH时，才输入 `APPLY`；它备份原文件、核对原/目标哈希并进行同目录原子替换。不认识的文件明确拒绝，不会尝试猜测适配，不会替你停/起DSH。**普通插件安装和接入过程不自动修改宿主。** 已经具备该契约的构建无需重复打补丁。

回滚同样需要先关闭DSH，再使用 `scripts/dsh-compat.ps1 -Runtime "<runtime目录>" -Rollback`。只有当前文件与已知补丁哈希一致、且存在本工具的原始备份与回执时才允许恢复；它不覆盖其它补丁或后续升级。移除记忆插件不自动移除宿主契约，避免影响可能使用相同契约的其它插件。

## 配置模型

不配置模型时也可以保存原话、进行词法检索、管理记忆与备份、使用生活规则和面板。语义索引需要你自己的嵌入服务；自动整理需要你自己的 OpenAI 兼容模型接口。未配置的任务会明确等待，不能当作已经完成。

GitHub/npm 新安装优先在首次设置卡填写模型地址、名称和新密钥。Windows 密钥使用 **当前用户 DPAPI** 加密保存，页面只显示是否已保存，不读回原值；密钥框留空保留原密钥。非 Windows 不通过卡片保存密钥，应使用配置指定的环境变量；本轮完整安装流程只按 Windows 验证，不宣称其它平台宿主安装已全部通过。

运行中保存模型配置后，先结束当前对话，再点击 **应用配置并重新连接**。该动作只停止并重启本插件管理的这个内核，不重启 DSH，也不根据端口或 PID 停止其它服务。

原 ZIP/`link:` 或显式 `brainConfigFile` 安装继续在原目录的 `private/config.json` 管理 `embed_url/embed_model`、`llm_url/llm_model`，密钥沿用原环境变量或本机密钥保存方式。设置卡对旧模型配置只读。不要删除自动生成的 `api_token`，不要将密钥发到聊天或提交仓库；手工改地址后正常停止再启动相应内核，不要只刷新网页。

后台整理默认积累12条消息或等待最多900秒，再开始一批，避免逐句付费整理；可在面板调整。原话和向量索引不必等待整理完成。开启远程模型会向自己配置的服务发送允许处理的原话，请先核对数据用途。

## 默认数据与权限边界

首次安装的所有者是中性的 `local-owner`，跨会话默认关闭，生活层默认关闭，不带预设角色或任何个人经历。需要时在面板手动开启。情绪采用明确事件和分轴衰减，不按关键词自动判断心情。完整规则见 [日常规则](DAILY-STATE-RULES.md)。

GitHub/npm 首次准备把 `.venv`、配置、数据库、队列、日志放在稳定的**用户数据目录**，Windows 默认位于 `%LOCALAPPDATA%\MemoryBrain\profiles\` 下的对应 profile 目录，实际完整位置以设置卡显示为准。代码所在的 `node_modules` 可以随插件更新替换，私人运行目录不会跟着删除；不同 profile 的安装不要误认为天然共用一张库。

原 ZIP/`link:` 和显式 `brainConfigFile` 安装保留既有位置：配置仍在原 `private/`，原话/索引/备份仍在原配置指定的数据目录，不自动搬迁。接入器会按 profile 生成独立队列；默认队列名为 `default`，同时运行多个 DSH 进程时应明确配置不同 `queueNamespace`，同一队列已有写入进程时第二个实例会拒绝占用。

以上都是安装者的私人文件，**再次分享时只分享原始压缩包或重新运行公开打包器**，不能把使用后的运行目录压缩发出去。

本包按个人本机可信账号设计，只监听回环地址。模型密钥和管理口令不进入发布包，不意味着同一系统账号下任意会话工具无法读取本机文件。多人/不可信工具部署应另加操作系统账号、沙箱和认证隔离；本包不宣称已提供该隔离。

## 卸载、升级与恢复

- 双击 `移除DSH接入.cmd`，选择同一runtime和profile，先预览再确认。只移除本包条目；正常重启DSH后停止接入。不会删除数据库、队列、人格或其它插件。
- 插件卸载不会删除独立内核的数据；旧 ZIP 安装需要时用 `停止忆核大脑.cmd` 正常停止。已有待发队列保留，不能当成可以随意删除的缓存。卸载代码不等于清空用户运行目录。
- 升级前在面板创建在线备份。GitHub/npm 更新只替换代码，本版首启管理器不执行跨版本 Python 环境升级：检测到旧环境时保留现状并显示需要维护，不在原环境中用 pip 覆盖。需要更新内核时应先在另一个环境验证，再按维护流程切换并保留旧环境、配置和数据。旧 ZIP 安装仍需正常停止内核后运行安装器。不要覆盖成别人的配置或数据。
- 接入器保留修改前的原字节备份。手工恢复时仅在 profile 未被其它操作继续修改的情况下恢复对应备份；否则逐项合并，避免覆盖后来的修改。
- DSH不兼容时，不要套用来源不明的补丁。请求级证据不写入历史是本包的必要条件，不能用“把记忆追加进聊天历史”冒充兼容。

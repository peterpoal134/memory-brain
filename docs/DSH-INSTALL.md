# 忆核大脑：DSH 插件安装包

这是一个完整的本机记忆项目：DSH 接入插件、独立 Python 内核、持久队列、原话与派生索引、3D 大脑和控制面板、角色/重要记忆工具、生活与情绪规则均在包内。不依赖 AstrBot，不包含任何人的既有记忆或人格。

## 安装前

- Windows 10/11；Python 3.10+（建议3.11）；Node.js 22+；已经安装的 DSH。
- 解压到普通用户可写的固定目录，避免系统目录。安装后不要直接移动目录；要移动时先正常停止并重新接入路径。
- 首次安装需要从 Python 官方包仓库下载 NumPy 和 Windows 时区依赖。包内有完整内核 wheel 和源码，无需编译前端；没有附带 Python、DSH、模型权重或付费模型额度。
- DSH 请求兼容性由公开插件入口核验：已有请求快照支持时使用 `native_snapshot`；匹配已核验原版构建时使用插件内 `scoped_agent_bridge`。后者是受限的进程内兼容适配，不是官方原生hook，不修改ASAR或宿主文件。未知构建拒绝接入，**不会仅凭版本号假定兼容**。具体范围见 [桌面兼容说明](DSH-DESKTOP-COMPAT.md)。

## 三步使用

1. 双击根目录的 `install.cmd`。它创建独立 `.venv`，校验包文件、安装内核，生成全新的本机配置和随机管理口令。遇到占用端口只选择空闲端口，不停止其它服务。安装失败窗口会保留错误。
2. 在DSH中先选择一个独立测试profile，进入原生 **插件 → 安装已有插件**，在安装来源文本框输入 `link:<解压目录绝对路径>`，把示例改为本包解压根目录的完整路径。这个目录必须含根 `package.json`，并已完成上一步生成 `.venv` 和 `private/config.json`。使用 `link:` 保留对完整固定目录的引用；不要直接拖入ZIP，也不要把底层 `adapters/dsh/xiaojiu-brain.mjs` 当成独立UI安装包。
3. 确认插件加载结果；宿主若要求重启，在方便时正常重启该profile。公开入口会核验请求兼容性并启动本包的独立内核，不修改宿主文件。也可双击 `open-panel.cmd` 打开3D首页，再进控制面板。桌面入口通过本机一次性票据登录，不需要手填管理口令。

如果profile里已有其它同用途记忆插件，请先在DSH插件管理中停用同用途的采集/召回项，避免重复；接入器会额外检查并拒绝部分已知叠加。原人格内容应保留；如果人格插件同时负责记忆注入，需要先分清职责。旧memory-core模型代理也应按你的部署情况检查，本插件不会擅自改变对话模型。

这里的安装入口是DSH原生插件管理页，不是只展示精选目录的dshmarket市场页。本包使用根 `package.json` 的 `dsh.bundle.patch` 声明加载 `adapters/dsh/memory-brain.mjs`。首次请先在测试profile验证，再决定是否接入常用profile。目录一旦被link引用，就不要删除或移动。

### 独立普通runtime的高级接入方式

已有明确runtime与profile路径时，也可双击 `connect-dsh.cmd`。输入使用的 **DSH runtime目录**（内含 `node_modules`）及目标profile的 `cordis.patch.yml` 完整路径。它先显示预览；输入 `y` 才备份并添加本包一个插件条目。再次接入会识别已有条目；模型路由、人格和其它插件不被自动重写。不要把桌面应用的ASAR文件当作runtime目录交给此工具。

高级预览方式（占位路径需改为自己的）：

```powershell
node scripts/register-dsh.mjs --runtime "<DSH runtime目录>" --profile-patch "<profile的cordis.patch.yml>" --package-root "<本包目录>"
```

加 `--apply` 才实际写入。备份位置和结果由命令报告，不包含令牌。直接CLI模式适合已经核对预览的使用者。

**插件管理器方式与接入器方式二选一**，同一profile不能重复加载。公开入口会从宿主自身模块范围解析运行时；解析失败会明确报错，不会扫描磁盘或下载另一套DSH。不要把缺少 `.venv/private/config.json` 的npm复制包当作零依赖插件：普通npm或tgz安装可能落到新的包目录，原解压目录的私人运行文件不会自动跟过去。面向本包的本地安装请使用已初始化完整目录的 `link:` 引用。

## 旧工具：仅供独立普通runtime使用

本轮桌面接入使用插件内兼容适配，**不需要解包、重打包或修改桌面ASAR，也不需要对stock Desktop运行旧宿主补丁工具**。未知桌面构建应停止接入并提供不含私密信息的兼容错误，不能删除guard强行启用。

包内仍保留公开、可回滚的旧请求快照补丁工具 `scripts/dsh-request-hook.mjs`，仅供独立、可写的普通runtime高级使用，支持范围由 `compat/dsh-request-messages.json` 的精确 **0.2.1-rc.5构建字节哈希** 限定。它不是本轮桌面安装的必经步骤，也不能用于ASAR。版本号相同但内容不同，不会强行套用。

需要时双击 `dsh-compat-check.cmd`：先只读检查。只有已知原版、并且你已经正常关闭使用该runtime的DSH时，才输入 `APPLY`；它备份原文件、核对原/目标哈希并进行同目录原子替换。不认识的文件明确拒绝，不会尝试猜测适配，不会替你停/起DSH。**普通插件安装和接入过程不自动修改宿主。** 已经具备该契约的构建无需重复打补丁。

回滚同样需要先关闭DSH，再使用 `scripts/dsh-compat.ps1 -Runtime "<runtime目录>" -Rollback`。只有当前文件与已知补丁哈希一致、且存在本工具的原始备份与回执时才允许恢复；它不覆盖其它补丁或后续升级。移除记忆插件不自动移除宿主契约，避免影响可能使用相同契约的其它插件。

## 配置模型

不配置模型时也可以保存原话、进行词法检索、管理记忆与备份、使用生活规则和面板。语义索引需要你自己的嵌入服务；自动整理需要你自己的 OpenAI 兼容模型接口。未配置的任务会明确等待，不能当作已经完成。

在自己机器的 `private/config.json` 设置 `embed_url/embed_model` 和 `llm_url/llm_model`；模型密钥使用 `embed_key_env/llm_key_env` 指定的环境变量，不要发到聊天里或提交仓库。不要删除自动生成的 `api_token`。改模型地址后正常停止并重启内核；不要只重启网页。

后台整理默认积累12条消息或等待最多900秒，再开始一批，避免逐句付费整理；可在面板调整。原话和向量索引不必等待整理完成。开启远程模型会向自己配置的服务发送允许处理的原话，请先核对数据用途。

## 默认数据与权限边界

首次安装的所有者是中性的 `local-owner`，跨会话默认关闭，生活层默认关闭，不带预设角色或任何个人经历。需要时在面板手动开启。情绪采用明确事件和分轴衰减，不按关键词自动判断心情。完整规则见 [日常规则](DAILY-STATE-RULES.md)。

配置在 `private/`，原话/索引/备份在配置指定的数据目录；本包默认 `data/`。接入器会按profile生成独立队列目录。插件管理器方式默认使用 `default` 队列名，同时运行多个DSH进程时应给它们明确配置不同的 `queueNamespace`；同一队列已有写入进程时第二个实例会拒绝占用。它们都是安装者的私人文件，**再次分享时只分享原始压缩包或重新运行公开打包器**，不能把使用后的整个目录压缩发出去。

本包按个人本机可信账号设计，只监听回环地址。模型密钥和管理口令不进入发布包，不意味着同一系统账号下任意会话工具无法读取本机文件。多人/不可信工具部署应另加操作系统账号、沙箱和认证隔离；本包不宣称已提供该隔离。

## 卸载、升级与恢复

- 双击 `remove-dsh.cmd`，选择同一runtime和profile，先预览再确认。只移除本包条目；正常重启DSH后停止接入。不会删除数据库、队列、人格或其它插件。
- 插件卸载不会强杀独立内核；需要时用 `stop-brain.cmd` 正常停止。已有待发队列保留，不能当成可以随意删除的缓存。
- 升级前在面板创建在线备份，正常停止本包内核，再升级文件；安装器会拒绝覆盖仍在运行的实例。保留自己的 `private/` 和数据目录，不要覆盖成别人的数据。
- 接入器保留修改前的原字节备份。手工恢复时仅在 profile 未被其它操作继续修改的情况下恢复对应备份；否则逐项合并，避免覆盖后来的修改。
- DSH不兼容时，不要套用来源不明的补丁。请求级证据不写入历史是本包的必要条件，不能用“把记忆追加进聊天历史”冒充兼容。

## Python测试与a13补文件说明

在解压根目录、使用已安装依赖的Python执行 `python -m unittest discover -s tests -p "test_*.py"`。Windows一体包可用 `.venv\Scripts\python.exe` 代替 `python`，避免误用另一个Python环境。macOS可以核验Python内核，但本包的CMD/PowerShell接入启动器仍以Windows为已验平台，不将Python测试等同于完整Mac宿主安装验证。

0.2.0a13公开包遗漏了本地工具 `scripts/verify_migration.py`，两处测试引用同一文件，因此会报两次 `ModuleNotFoundError`。这是发布文件遗漏，不需要安装名叫 `scripts` 的第三方包。a14已补齐工具和本地包标识；已有a13也可以仅补入这两个文件，不需要动数据库或重新配置模型。

公开打包器现在先核对本地导入依赖，再从最终候选ZIP解压运行原始Python测试。出现失败、错误或跳过均停止发布，不用源码目录的成绩代替分发包成绩。发布者运行 `scripts/build_plugin_release.py` 前需要安装构建依赖setuptools/wheel；可用 `--test-python <已安装运行依赖的Python>` 指定检查环境。

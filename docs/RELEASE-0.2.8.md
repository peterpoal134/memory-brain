# 0.2.8 已送达队列清理

首次补采大量历史后，旧版每秒同步列出整个 `delivered` 目录，再逐个查询文件时间。目录积累数千份文件时，空闲的投递队列也会反复占用 DSH 的 JavaScript 线程。

现在每秒的投递任务只负责归档和发送。单独的维护任务每分钟异步处理最多 200 个目录条目，下一批从上次的位置继续。已送达文件仍按修改时间保留七天。卸载会等待已发出的维护操作结束，再释放队列写锁。

维护只处理过期的已送达副本。已送达确认和去重索引会保留，因此重启后仍可确认投递和识别重复消息。待发与失败文件继续保留，正式记忆库无需迁移。

Windows 隔离对照中，3,500 份文件从每轮 3,500 次同步查询改为每批最多 200 次异步查询。另验证了过期文件跨批清理、卸载期间的写锁和重启恢复。启动时的队列恢复和历史补采仍各有自己的 I/O 成本。

从旧版更新时，先结束当前对话，按[维护说明](MAINTENANCE.md)备份，并核对内核升级方式。首次设置管理器要求插件与托管内核的版本匹配。显式配置外部内核的安装需单独维护内核。保留已有配置、队列和记忆数据库，完成切换后按 DSH 提示重载。若加载仍长时间停滞，请记录插件版本、发生时间、当时所处阶段、已送达文件数量和脱敏诊断码，便于判断耗时发生在哪一步。

# 角色、约定与明确保留的记忆

控制面板的“角色与约定”把四个来源分开：

- **宿主人格与行为准则**：来自安装者登记的宿主配置快照，只读展示原文、范围、时间和文件哈希。来源文件变化会标记过期；快照不等于已经捕获了当前模型请求，不自动覆盖宿主文件。
- **表达偏好与自我笔记**：由所有者在面板填写，沿用自我扩展开关；配套DSH适配器通过独立、限额的请求通道获取，不依赖记忆召回成功。
- **显式行为准则**：所有者单独新增、修改、启停或删除，具有版本、修订、用户层优先级与会话范围。普通聊天、派生事实和宿主人格快照不会自动进入此层。
- **重要叮嘱**：明确保留操作成功后，展示实际记录、重要性、置顶状态和原话出处。重要性是保留策略，不是事实真假或模型确信程度。

这些是外部配置、用户管理的笔记和有来源的记录，不是对模型内部参数、私有推理或真实感受的读取。

## 独立准则与请求上下文

准则层默认空白、关闭，与自我档案开关分开。最多50项，每项正文最多1000字符；可选择所有者范围，或绑定一个明确会话。条目还可以单独关闭。优先级为0～100，只决定此用户层内部顺序，**不能覆盖系统、开发者等更高层指令**。

实际修改会增加准则层 `version`，条目修改增加其 `revision`，并保留创建/更新时间。相同内容的重复更新不增加修订；有明确ID的相同新增重放不会重复创建。最近50次修改历史仅保存在所有者本地配置中，不随角色段注入模型。删除不存在的条目为无变化操作。

配套适配器调用 `POST /v1/context/profile`，独立于原话ACK、记忆召回和生活状态。整段额度最多 **384个估算tokens**，包括说明与条目标签；使用 `ceil(UTF-8字节数/3)` 估算，不是模型实际usage。先按优先级降序、ID升序选择适用准则，再放表达偏好和按创建时间/ID排序的自我笔记。每项必须完整装入，不截断句子来假装已加载全部语义；装不下的条目留在配置里，并在 `trace.omitted_ids/omitted_count` 报告。

返回的trace包含配置版本、准则版本、实际装入ID和估算用量。未开启、没有适用条目时返回空段；超时或服务不支持时明确降级。直接调用旧式 `/v1/recall` 的客户端仍可能走兼容的、与证据共用预算的自我笔记附加路径；独立准则携带需要支持新通道的适配器，不能把两种路径混为一谈。

同一真人消息的工具续轮复用第一次取得的角色段；下一条真人消息重新获取。面板更新不会追改已经冻结的同一轮。角色段只加入当前请求快照，不作为新消息写进会话历史；模型自己在回复中生成的文字仍可能由宿主正常保存。

默认独立通道各自最多等待800ms，并与记忆召回并行；适配器等待这几路有界结果后继续，所以慢召回仍可能占用默认约3秒的前置预算。独立预算避免互相挤掉内容，不代表零延迟或零tokens。这里不新增逐轮分类模型，但真实聊天输入、工具说明和工具续轮仍有上下文成本。

管理接口为 `GET/PATCH /v1/standards`、`DELETE /v1/standards/<id>`；它们和自我档案管理一样需要所有者鉴权。准则不是事实证据，也不是从重要记忆反推出来的权限。

## 聊天里的明确要求

DSH适配器在原生工具服务可用时提供 `memory_remember_important`。当真人用户明确要求长期记住某项信息时，主聊天模型可以调用工具；它必须等成功回执后才能声称已经完成。自然语言意图由主模型理解，不另起每轮分类调用，也不使用“出现某几个关键词就置顶”的规则。

工具绑定实际当前会话与当前真人消息，不能让模型指定所有者或伪造另一个会话。默认保存当前用户原话，也可引用该会话中更早的可见用户消息及字符区间。后端验证所有者、会话、用户来源、时间及原文跨度，逐字保存；助手猜测、工具输出、导入笔记和未来数据不能通过这条路径冒充真人叮嘱。

每个实际来源片段保存为带出处的索引，默认重要性 **0.95、置顶**，原话独立保留。它不等待后台12条批次，不重写事实，也不把计划当成完成。调用和重试有幂等回执，不重复造原话。普通消息仍照常归档，模型未调用此工具时，不能仅凭聊天中的“记住了”当成重要记忆已经建立。

工具本身不调用提炼模型，但描述会增加少量工具输入，实际保存发生时可能多一个工具步骤；不能宣传成完全零tokens。

## 置顶与保密

置顶的派生记录不参与普通自动衰减与归档。检索仍受相关性、证据预算、有效来源和披露策略约束，不会把全部置顶内容塞进每轮对话。可以在面板取消置顶、调整重要性或归档；重放过去同一保存请求不会悄悄覆盖之后的这些人工选择。

明确保留不会解除已有保密限制。工具可以进一步收紧披露级别，受限内容在“角色与约定”中保持占位；核对出处只显示所引用的片段，不带出同一原话中未引用的相邻内容。

## 登记宿主人格来源

独立服务可在本地配置中设置可选 `profile_sources_file`，指向安装者管理的JSON快照。未配置时面板如实显示“尚未登记”，不会编造人格。文件结构为：

```json
{"schema_version":1,"observed_at":1794100000,"sources":[{"id":"example","title":"聊天人格与准则","kind":"host_persona","host":"Example host","role_scope":"default preset","text":"安装者明确登记的原文","source_path":"C:/example/profile.json","source_sha256":"64位SHA256"}]}
```

快照和真实私有配置不得打入公开发行包。它只描述已登记来源，控制面板不会通过URL参数读取任意本地文件，也不会把宿主的模型凭据或完整配置复制出来。

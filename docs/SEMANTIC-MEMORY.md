# 语义记忆、时间与关系的真实边界

本层让原话更容易被找到和核对，不把模型生成的索引变成已证实事实。它与所有者明确管理的角色、行为准则分开；功能检查不能替代新的完整记忆测评。

## 原话、提案与说话者

原话按所有者、会话、角色、记录时间和字符跨度保存。检索先检查身份范围、截止时间、来源有效性和披露规则，再组织候选。输出证据会回读实际引用的原文跨度，不靠摘要正文替代原话，也不顺带带出同一消息未引用的相邻文字。

摘要和事实索引可以带结构化主张，规范化后的形式称为canonical claim。它统一 `subject/predicate/value/assertion_type`，兼容旧的平铺 `attribute` 字段和嵌套 `claim` 对象；不完整或互相冲突的字段不被强行合并为确定主张。

这些仍是**未核实提案**，`claims_verified` 保持false。引用范围存在，只证明这些原文可回读，不证明提案中的主体、属性、值及其含义都已逐项成立。不能把“canonical”理解为“事实已经认证”，也不能把高相关分、重要性或置顶当作真假判断。

来源引用和角色由回读的记录生成，不接受模型自称的来源ID或用户权威作为证明。说话者与事实主体分开：用户谈到第三人的事，不自动变成用户自己的事实；助手的猜测、建议和承诺不升级为用户陈述。旧库导入笔记另外标记为非对话原话、原说话者未核实，不能据其存储兼容角色推断真实说话者。

同一主体和属性出现不同主张时，输出可保留未解决的候选；没有明确依据就不一律取最新。规范化不是自动纠错、实体身份确认或完整事实一致性证明，最终回答仍需要结合原话及适用时间核对。

可选的“尝试寻找相关后续原话”默认关闭。开启后，只在已允许读取且来源可回查的提案中，根据完全一致的主体与属性寻找较晚的用户原话；模型提议的主体还必须逐字存在于用户来源。它只提供少量候选，不能证实是同一事项、不能因为较晚就判定覆盖旧说法，也不保证找到所有更新。

对“是 A 还是 B”式提问，如果两个选项分别出现在已选中的不同用户原话中，系统可在预算允许时增加存疑提示；相同文本不证明同一对象或互相矛盾，最终模型也不保证遵循。

## 泛用时间指代，而非事件发生认证

时间模块使用有限、公开的日期语法，不调用模型来猜日期，不含题目情节规则。可处理的形式包括明确年月日、部分中英文相对日、日历周/星期和明确以发言时点为基准的天数或周数偏移；不是任意自然语言时间理解器。

时间表达必须实际出现在已引用的原文跨度中。换算按该来源消息的记录时点和服务配置时区的日历进行，不使用提问当天、摘要批次结束时间或机器当前日期代替来源锚点。保留可验证的原时间偏移信息；日期区间的结束边界不包含在内。

以下情形不补猜一个确定日期：

- 缺年份、日期顺序不明，或表达本身模糊。
- 同一表达可能来自多个不同的消息锚点，且没有唯一指定。
- 平铺和嵌套提案的表达或锚点相互冲突，包括规范化后再次回读的情况。
- `N days before/after/later` 等需要另一个事件作锚点的裸表达。
- 旧导入笔记的时间只是旧记录时间，原发言时刻未核实。
- 来源时间、字符范围、时区或日期无效，以及语法暂不支持的表达。

这些情况返回ambiguous或unsupported等未确定状态，不把模型给出的 `start/status/completed` 当成已验证结果。未引用的时间提案不能生成已解析的日期说明；结构化元数据中的原提案仍不等于证据。

请求中的时间说明只扫描实际选中的来源跨度，并明确表示“日期指代换算，不代表事件已发生”。计划、条件、假设、转述、故事和已发生事实仍需保持各自性质。即使“明天”能换成一个日期，也不能据此把“打算参加”写成“已经参加”。

时间注释也占记忆证据预算。装不下时报告遗漏，不通过额外说明悄悄超过额度；未找到日期说明不等于历史没有提到日期。

## 一跳关系候选导航

关系模块使用已经通过来源、范围和披露检查的主张作为索引。名字只做Unicode兼容形式、大小写和空白规范化，然后精确匹配；不自动猜别名、昵称、同名人物或代词身份。

当问题提到一个已存在的主体名时，可先选这个主体的主张；如果某个值恰好也是另一个已存在的主体名，再导航一跳，补充有限的候选。它不创造关系边、不改写原记录，也不因导航成功就确认关系为真。最终请求仍从实际来源组织证据。

这是有范围和数量限制的候选入口，**不是完整知识图谱**。它不提供任意多跳推理、自动实体消歧、完整关系覆盖或图谱级事实认证。精确名字不一致时可能找不到相关候选；同名不同人仍需保留歧义。

## 角色准则独立于事实检索

所有者填写的自我档案、表达偏好和显式准则通过独立角色通道获取，不能由普通记忆或模型提案自动升级。准则有层版本、条目修订、用户层内部优先级及所有者/指定会话范围；它们服从系统、开发者等更高层指令，不是事实证据。

配套DSH适配器给整个角色段独立的384个估算tokens额度，先选择适用准则，再放表达偏好和自我笔记。只装入完整条目，超限的ID和数量留在trace中；关闭或无适用内容时返回空段。宿主人格文件快照仅供核对，不自动进入这个通道。详细管理方式见 [角色与明确保留](PROFILE-IMPORTANT.md)。

同一真人消息的工具续步复用首次取得的上下文，下一条真人消息刷新。注入是请求快照，不新写入会话历史；模型自己生成的回复仍可能被宿主正常保存。修改面板配置不会追改已经冻结的同一轮。

## 成本与验证口径

字段规范化、日期换算、一跳导航及角色段组织本身不另起逐轮分类模型。生成摘要和事实提案仍可能使用已配置的后台整理模型，语义检索也可能调用嵌入或重排接口。

证据、时间说明、角色准则、生活状态、工具说明及正常工具续轮都会消耗聊天上下文。384角色额度、160生活额度和默认1200证据额度是不同文本段的估算限制，使用 `ceil(UTF-8字节数/3)`，不等同于供应商实际usage，也不包含所有消息封装和宿主输入成本。

独立角色和生活请求默认各自最多等待800ms，和记忆召回并行；默认慢召回仍可能让请求前置等待约3秒。独立通道解决互相挤掉内容及一起丢失的问题，不保证零延迟。

本说明陈述实现能力及限制，不给出新的大规模benchmark分数，不承诺真实等待45天的保持率。合成回归、实际宿主接线与完整未知题评测应分别报告；也不能由代码已写好推断某台机器已经部署启用。

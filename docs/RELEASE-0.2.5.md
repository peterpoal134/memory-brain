# 忆核大脑 0.2.5 稳定性修订

插件与 Python 内核版本均为 `0.2.5`。继承 0.2.4 的有界去重缓存、会话卸载、回合外裁剪保护和预算单位修复。本版不调整记忆评分、模型路由或隐私边界，不把稳定性回归作为新的记忆能力分数。

## 修复

- 设置路由中途注册失败时，安全等待所有异步清理结果，防止清理 Promise 拒绝成为未处理异常而导致 DSH 退出。清理本身失败仍记录类别告警，不宣称失败路由已经删除。
- SQLite 提交失败或操作取消时同样回滚，避免连接留在未结算事务、随后正常写入持续失败。
- 同一连接存在未结算事务时明确拒绝备份，不等待自己释放写锁；备份目标独占创建，不覆盖旧备份，失败时只清理由本次创建的不完整文件。
- 停止时若维护线程仍在工作，明确返回未完成，不继续关闭其正在使用的数据库连接或等待该锁。
- 本地 HTTP 最多同时处理 32 个连接。空闲请求读取限 10 秒，正文读取有独立 10 秒总时限；超载返回 503，正文超时返回 408，均不算原话保存成功。持久队列保留未确认消息后重试。
- 浏览器在写响应头或正文时断开，不再触发再次写错误响应的异常连锁。
- 非流式上游 JSON 默认最多接收 16 MiB；超限明确失败并关闭连接，不把部分响应当作结果。流式内容分段读，不按对端声明的一整块大小分配。有限正数的总时限继续生效。
- `model_timeout` 必须为大于 0、不超过 600 秒的有限数值，默认 45 秒不变。

## 验证与限制

验证使用合成数据、真实 SQLite 和本地 HTTP 桩，覆盖提交失败恢复、取消、并发备份、慢请求、断连、上游超大响应、停止时锁竞争和 Node 严格未处理异常模式。没有使用私人对话，也没有调用真实模型完成这些验证。

这些是已复现错误路径的修复，不是任意硬件或无限并发下不会崩溃的证明。线程上限不是整个进程内存上限；大范围检索、完整导出及上游模型本身仍有数据量相关的资源成本。请求头的 10 秒限制为空闲读取时限，不是完整请求头的总时限。业务已经开始后，不会因浏览器断开而擅自取消已提交的原话。

已有正常配置和数据库无需重建。升级前按[维护说明](MAINTENANCE.md)备份，保留原配置、owner、数据目录和队列命名空间，使用新目录并排安装。关闭本插件之外的宿主压缩策略不在本次升级内。公开包排除密钥、人格、聊天记录、记忆库、队列和备份。

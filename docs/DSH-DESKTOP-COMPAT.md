# DSH Desktop请求兼容说明

公开插件入口是根包的 `adapters/dsh/memory-brain.mjs`。入口先核验宿主，再启用采集和注入；不会为了让界面显示成功而删掉兼容检查。本次桌面接入不解包或修改ASAR，不写宿主运行文件，也不自动重启DSH。

当前为 `0.2.9` 框架正式版，插件与 Python 内核均为 `0.2.9`。记忆注入延续已核验的兼容路径，宿主范围以本页列明的已核验构建及其等价形式为准；已有安装按[维护说明](MAINTENANCE.md)并排升级。本轮接入检查使用 Windows 隔离测试宿主，直接套用时应在自己的实际环境检查采集与召回。长期日常观察和更多模型／硬件实测作为后续验证持续补充，官方 `0.2.2-rc.3` 的已核验构建始于 [0.2.6](RELEASE-0.2.6.md)。队列维护变化见 [0.2.8 发布说明](RELEASE-0.2.8.md)。

## 接入模式

| 模式 | 选择条件 | 实际处理 |
| --- | --- | --- |
| `native_snapshot` | 完整源码及运行中的方法均匹配已核验的本地快照补丁 | 沿用该补丁的请求快照路径 |
| `scoped_agent_bridge` | 完整 AgentLoop 源码和实际实例方法均匹配已核验的无快照构建 | 插件在当前进程内适配指定agent实例的 `step/buildRequest`，把最终决议中的字符串加入本次冻结请求 |
| `archive_only` | 在插件配置显式选择仅归档，且宿主提供可核对的会话事件与快照 | 只把启用后的正式原话写入独立归档队列，可在面板查找 |
| `diagnostic_only` | 尚未核验的源码指纹、缺少必要模块或无法确认宿主 | 仅提供受鉴权的只读环境诊断；采集和召回未接入 |

模式名只说明本包选用了哪条路径，不代表对所有同版本宿主或官方hook的认证。版本号相同、文件不同也可能不兼容。

插件优先核对原始 SHA-256，也接受单个初始 UTF-8 BOM 及 LF/CRLF 换行差异。下列构建各有独立的文件和方法指纹。已记录完整语法指纹的构建，还支持经下文说明校验的格式变化。

```text
官方 0.2.1-rc.2 / rc.5 原版：
cf57e3ecd487ac5c2553455aaa5cef2c6fb41e6bd61be5aa455675d1d7193033
官方 0.2.2-rc.1：
a6fa8e0c7c90191caf5f4a3bb5c624a86e9845cf3c79d020b71420d0e20ae4c1
官方 0.2.2-rc.2 / rc.3：
f09f60814d4e96a880f41b9fc3832f33c56a28f954f48810d8439ce83ad6ffa8
DSHA build190 公开工具校验补丁重建：
a8b456b07ad59a77b65be20702cb07fb202e646f7783c5f0bbd3f8d3d48d4937
```

对已记录语法指纹的构建，文件哈希不同后会用 JavaScript 解析器比对完整模块，保留影响执行的换行、字面量和指令。两处运行中方法也需独立匹配。通过这一途径时诊断原因为 `verified_syntax_equivalent`。代码结构有变化、超出解析大小限制且文件哈希未知、或运行方法被其他扩展替换时，停止本插件的自动注入。校验只读取源文件，不改写宿主。DSHA build190 仍按完整文件指纹及 BOM／换行等价规则核对。

官方 npm 0.2.2-rc.2、Electron ASAR 的 0.2.2-rc.3 与 0.2.1-rc.5 已做隔离请求验收。也用实际 Electron 验证了加注释后原始哈希变化的 rc.3。第三方同版本构建依实际源码与运行方法核验。独立Android项目 [DSHA](https://github.com/DSH-APP/DSHA) 的 build190 会修改工具调用校验；本包保留这项校验，对应身份按其固定提交 `c750348a4d4b18edcb165a93b4ca66403b040b4c` 的公开补丁重建，**没有从群友手机或APK提取最终模块**。隔离重建源码的接入检查不等于手机安装验收，手机的Python环境、配置页、后台生命周期仍需实测。不能照Windows的`.cmd`步骤安装，也不能据此承诺所有DSHA版本均支持。

## 仅归档模式

如果已确认四个宿主模块来自同一套运行环境，但提示 `unknown_loop_fingerprint`，可以在**现有的一处 `memory-brain` 插件配置**中加入 `archiveOnly: true`。重新加载后，在配置页明确点击「启用归档」。缺少会话服务、日志形状不匹配或模块身份不一致时，按诊断处理。进程重启或重新加载后，需要在该页再次确认启用。

仅归档使用 DSH 的 `session/event` 等公开会话事件，核对真实会话身份和已提交事件。采集范围从本次启用之后开始，不扫入先前对话、分支继承、工具输出或插件上下文。消息通过独立的本地持久队列投递；对话内自动召回、注入、压缩、工具和用量采集均未启用。面板可手动检索，内核后台模型仍按用户自己的设置运行。需要完整接入时，在核验过的宿主移除 `archiveOnly`，再确保只启用一份插件。

## 桥的作用范围与清理

`scoped_agent_bridge` 是本插件自带的受限进程内兼容适配，**不是DSH正式提供的原生请求hook**。它只在核验过的agent实例上安装自己的方法包装器，不替换全局原型、不劫持模型路由，也不改变持久化的Session消息。

桥绑定当前agent、turn、step及其取消信号，在实际 `step(decision)` 入口读取最终pre-step决议。外层插件删除、替换或拒绝的材料不会被早先缓存重新注入。构建请求时只创建本次使用的新冻结消息数组，保持宿主原请求不变；空材料不添加消息。取消、回合结束、实例不匹配或兼容检查失败时清理绑定，不将旧段落带到另一轮或另一agent。

同一真人问题的工具续步仍复用适配器第一次取得的证据、角色和生活材料；下一条真人消息再刷新。它不是每次工具返回都重新检索。桥卸载时恢复自己仍拥有的实例方法；若其它扩展后来替换了方法，不覆盖对方的修改。正在执行的调用按自身清理边界处理，不通过强杀进程完成卸载。

“不写历史”特指注入材料不作为 `user/message` 或 `system/message` 追加到Session。模型正常生成的回复和推理仍由宿主按其现有机制处理，不能承诺模型永远不在答复中复述这些资料。

## Windows本地安装方式

从 a17 起，通过 GitHub/npm 或市场新安装时，可直接在插件详情的配置页使用 [首次设置引导](DSH-FIRST-RUN.md)。它在独立用户目录准备运行环境，不要求 npm 代码目录已经存在 `.venv/private`；只有用户点击初始化才安装依赖。以下是仍然支持的 ZIP/link 本机安装方式。

1. 在固定、普通用户可写目录解压完整公开包，先运行 `安装.cmd`，生成该目录自己的 `.venv` 和 `private/config.json`。
2. 建议先用空白测试profile。在DSH原生插件管理页的“安装已有插件”来源文本框填写 `link:D:/MemoryBrain`，将示例替换为实际解压目录。该目录必须包含根 `package.json`。
3. 根包通过 `dsh.bundle.patch` 加载公开入口。不要同时再加载底层适配器或接入器生成的重复条目。

ZIP是分发容器，不是这个文本框可直接解包安装的插件格式。`link:` 保留完整固定目录；不要把使用后的私人配置复制进npm包。普通npm/tgz安装不会复制原解压目录的私人配置；新安装通过首次设置创建独立运行环境，已有本机配置则保持原地使用。本包没有Python自动安装的npm生命周期脚本，不能把“包已列入插件页”当作内核和请求注入都已验证。

服务地址、管理口令、数据目录由本机配置提供，不在文档或包内预置任何人的凭据。宿主模块只能从其自身解析范围取得，不下载另一份宿主，也不把不相关runtime伪装成当前桌面的实现。详细安装和配置见 [DSH安装说明](DSH-INSTALL.md)。

## 不兼容时怎么处理

公开入口先发现当前宿主模块，再进行构建核验。两步失败的原因不同：

| 原因码 | 含义 |
| --- | --- |
| `dsh_runtime_not_resolved` | 尚未发现可读取的当前宿主运行模块，未进入构建核验 |
| `required_modules_missing` | 已找到候选目录，但所需模块不完整 |
| `unknown_loop_fingerprint` | 已读取核心模块，但它不属于当前已核验构建 |
| `node_22_or_later_required` | 当前宿主 Node 版本不满足要求 |

桌面版可能将模块放在 `resources/app.asar/dsh/node_modules` 内。0.2.3 补查当前桌面宿主参数和 Electron 的固定打包位置，并沿用同一套模块，不解包到另一个目录模拟宿主。普通 Node 进程不能因此获得 Electron 的 ASAR 文件系统能力；单独在外部 Node 中运行报告脚本，与桌面进程内部解析并非同一环境。

发现失败或构建未知时，默认显示只读诊断，不把整个插件报成初始化失败。诊断包括版本、模块 SHA、平台和发现状态；**不会读取私人配置，不采集、不召回，也不允许初始化、启动、保存模型或通过该卡打开面板**。若宿主连原生设置路由也不提供，则给出安全诊断提示，不创建匿名替代入口。

`allowUnverified` 是内部发现函数用于返回诊断结果的参数，不是启用未知构建的开关。它不会跳过后续检查，也不会把 `diagnostic_only` 变成可采集或可注入状态。不要修改指纹表或删除校验来制造“已连接”。

请复制安全诊断协助核验，不附聊天正文、私人路径或令牌。界面会区分模块未发现与构建未核验；已独立运行的内核与原面板不因此停止。对尚未拿到诊断的其他电脑，不仅凭相同版本号承诺其打包布局和行为完全相同。

旧的 `scripts/dsh-request-hook.mjs` 和 `DSH兼容性检查.cmd` 仍保留给独立、可写的普通runtime高级使用；它们的精确哈希范围和回滚方式由 `compat/dsh-request-messages.json` 定义，**不是本次stock Desktop桥的安装步骤，不能用于ASAR**。普通公开入口不会自动运行这些工具。

启用后用独立的非敏感会话确认：原话写入有明确回执；模型实际请求含本轮材料；Session 没有新增注入正文；工具续步与另一 agent 不串材料；关闭或卸载后停止注入。兼容记录仅适用于列明的宿主构建。

## 从旧插件更新到 0.2.6

若诊断显示 DSH `0.2.2-rc.3`、loop 指纹 `f09f6081…`、
`unknown_loop_fingerprint`，这是旧插件缺少新宿主构建记录。无需重装 DSH、清空数据库或修改模型。

1. 先完成当前对话，并按维护说明备份已有数据；保留原配置、管理口令、数据库和持久队列。
2. GitHub 安装将插件来源更新到本仓库 `v0.2.6` 标签，再按 DSH 提示重载插件或正常重启。
   ZIP/link 安装须在保留配置和数据的前提下更新代码；不要删除 `private` 或待发队列。
3. 打开插件配置，核对插件版本 `0.2.6`、loop 完整指纹及模式 `scoped_agent_bridge`。
4. 在非敏感测试会话说一句事实，再提问核对原话回执和召回。只打开 3D 面板不能证明 DSH 已接入。

新建空环境时使用完整 0.2.6 安装包。已有 Python 内核环境需要升级时继续按维护流程并排准备；
宿主适配不要求清空、迁移或重新嵌入既有记忆。

本轮使用官方 npm 组件在隔离环境验证真实 AgentLoop、原话归档、工具续步、并发会话、
请求级注入与卸载恢复；没有修改或替代宿主方法正文。模型响应由本地测试服务提供，
证明接入机制，不冒充记忆能力评分。独立 Android App、其它重新打包的桌面构建仍需核验实际诊断。

## 0.2.7：分包布局恢复与阶段诊断

某些分包或符号链接布局中，Node 解析到的 AgentLoop 实际文件不在宿主表面目录下。
旧版从该文件固定向上推断目录，若只找到 loop、缺少其它必需模块，会提前结束发现。
本版可继续检查同一 Node anchor 声明的有限模块搜索根，核对完整宿主。

新路径逐一核验 loop、session、llm、tools 的真实文件身份，并检查 loop 自身解析的 helper 身份。
只共享一个 loop 文件不够；其它模块来自不同副本时保持诊断。完整候选的未知指纹仍停止接入，
不能再找旧版构建冒充当前宿主。搜索次数与诊断数组都有上限，不递归扫描磁盘。

| 原因 | 配置页含义 |
|---|---|
| `asar_runtime_unavailable` | 检测到打包目录，但当前进程无法读取内部模块；不能单凭此项认定是权限问题 |
| `runtime_access_denied` | 系统明确拒绝读取宿主位置 |
| `required_modules_missing` | 识别到了宿主线索，但必需模块不完整 |
| `required_modules_unreadable` | 一个或多个必需模块读取失败，例如权限、I/O 或资源错误 |
| `host_module_identity_mismatch` | 同一发现路径中出现不同来源的模块副本，拒绝混用 |
| `unknown_loop_fingerprint` | 已找到完整模块，但源码构建未核验 |

“复制环境诊断”新增 `read_errors` 和 `discovery.attempts`，只记录模块标签、阶段、
固定错误类别与布局类型，不输出完整路径、异常正文、令牌、配置或聊天内容。
`asar_enabled` 仅表示可识别的 Electron 进程是否关闭了 ASAR 支持，不保证具体文件必然可读。

### 自动发现仍失败时

1. 保留现有配置、原话库和队列，先查看配置页的明确原因；不要反复清配置、清库重装。
2. 确认升级后当前加载的插件版本确实为 0.2.7；完成当前对话后按宿主提示重载。
3. 对确定当前宿主实际目录的高级用户，原有插件配置 `runtimePath` 可显式指定该目录。
   示例 `{"runtimePath":"D:/DSH/resources/app.asar/dsh"}` 必须换成自己的当前宿主路径；
   在 **DSH 插件宿主进程内**检查，而非用外部普通 Node 来推断 Electron 的访问能力。
   该字段是位置提示，仍检查模块及源码指纹；不会使普通 Node 获得 ASAR 能力。
4. 不要指向另行下载或解压的第二份 runtime，也不要删除指纹校验。
   如果当前进程本身无法读取打包模块，需要适配其真实宿主加载方式；单改一个 exists 为 resolve 不能通用解决。

显式 `runtimePath` 和 `XIAOJIU_DSH_RUNTIME` 保持权威：指定的路径不完整或未核验时，
不会静默换用另一份宿主。所有者配置、数据库和模型路由均不由发现过程改写。

本版补充真实 Electron ASAR 内部的自动发现检查以及普通 Node 的失败对照；
独立 Android 和其他重新打包版本仍以实际环境诊断为准，不将一台电脑的成功泛化到所有环境。

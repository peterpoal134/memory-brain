# DSH Desktop请求兼容说明

公开插件入口是根包的 `adapters/dsh/memory-brain.mjs`。入口先核验宿主，再启用采集和注入；不会为了让界面显示成功而删掉兼容检查。本次桌面接入不解包或修改ASAR，不写宿主运行文件，也不自动重启DSH。

## 两种请求注入路径

| 模式 | 选择条件 | 实际处理 |
| --- | --- | --- |
| `native_snapshot` | AgentLoop源码同时具备 `withRequestMessages()`、对应调用点和 `decision.requestMessages` 消费标记 | 保持已有宿主请求快照路径 |
| `scoped_agent_bridge` | 不具备上述路径，但完整AgentLoop文件SHA-256与本包核验的stock构建相同，随后实际实例方法指纹也匹配 | 插件在当前进程内适配指定agent实例的 `step/buildRequest`，把最终决议中的字符串加入本次冻结请求 |

模式名只说明本包选用了哪条路径，不代表对所有同版本宿主或官方hook的认证。版本号相同、文件不同也可能不兼容。

目前允许stock桥的完整AgentLoop文件SHA-256只有：

```text
cf57e3ecd487ac5c2553455aaa5cef2c6fb41e6bd61be5aa455675d1d7193033
```

完整文件匹配后，还会对实际agent的 `step()` 和 `buildRequest()` 函数逐一核对精确指纹；不能仅复制版本号或增加一个空的同名函数冒充支持。运行时若有其它扩展替换这些方法，桥不会把未知方法当成已核验实现。DSH升级、重构或其它扩展改变相关方法后，必须重新验证兼容范围。

## 桥的作用范围与清理

`scoped_agent_bridge` 是本插件自带的受限进程内兼容适配，**不是DSH正式提供的原生请求hook**。它只在核验过的agent实例上安装自己的方法包装器，不替换全局原型、不劫持模型路由，也不改变持久化的Session消息。

桥绑定当前agent、turn、step及其取消信号，在实际 `step(decision)` 入口读取最终pre-step决议。外层插件删除、替换或拒绝的材料不会被早先缓存重新注入。构建请求时只创建本次使用的新冻结消息数组，保持宿主原请求不变；空材料不添加消息。取消、回合结束、实例不匹配或兼容检查失败时清理绑定，不将旧段落带到另一轮或另一agent。

同一真人问题的工具续步仍复用适配器第一次取得的证据、角色和生活材料；下一条真人消息再刷新。它不是每次工具返回都重新检索。桥卸载时恢复自己仍拥有的实例方法；若其它扩展后来替换了方法，不覆盖对方的修改。正在执行的调用按自身清理边界处理，不通过强杀进程完成卸载。

“不写历史”特指注入材料不作为 `user/message` 或 `system/message` 追加到Session。模型正常生成的回复和推理仍由宿主按其现有机制处理，不能承诺模型永远不在答复中复述这些资料。

## 本地安装方式

1. 在固定、普通用户可写目录解压完整公开包，先运行 `install.cmd`，生成该目录自己的 `.venv` 和 `private/config.json`。
2. 建议先用空白测试profile。在DSH原生插件管理页的“安装已有插件”来源文本框填写 `link:<解压目录绝对路径>`，将示例替换为实际解压目录。该目录必须包含根 `package.json`。
3. 根包通过 `dsh.bundle.patch` 加载公开入口。不要同时再加载底层适配器或接入器生成的重复条目。

ZIP是分发容器，不是这个文本框可直接解包安装的插件格式。`link:` 保留完整固定目录；不要把使用后的私人配置复制进npm包。普通npm/tgz安装到新目录时，不会自动拥有原解压目录的Python环境和私人配置。本包没有Python自动安装的npm生命周期脚本，不能把“包已列入插件页”当作内核和请求注入都已验证。

服务地址、管理口令、数据目录由本机配置提供，不在文档或包内预置任何人的凭据。宿主模块只能从其自身解析范围取得，不下载另一份宿主，也不把不相关runtime伪装成当前桌面的实现。详细安装和配置见 [DSH安装说明](DSH-INSTALL.md)。

## 不兼容时怎么处理

出现 `dsh_request_messages_hook_required` 或方法指纹错误时，保留不含凭据、私人正文的错误类别及DSH版本信息，停在兼容失败状态。不要删检查、把记忆追加进聊天历史、直接改全局原型，或修改桌面ASAR来让错误消失。独立内核与面板可以继续单独使用。

旧的 `scripts/dsh-request-hook.mjs` 和 `dsh-compat-check.cmd` 仍保留给独立、可写的普通runtime高级使用；它们的精确哈希范围和回滚方式由 `compat/dsh-request-messages.json` 定义，**不是本次stock Desktop桥的安装步骤，不能用于ASAR**。普通公开入口不会自动运行这些工具。

启用后应以独立合成会话检查：原话写入有明确回执；模型实际请求含本轮材料；Session没有新增注入正文；工具续步与另一agent不串材料；关闭或卸载后停止注入。兼容通过不代表完整记忆能力评测，也不是对所有 DSH 桌面版本的承诺。
